# Conference chain adapters

These adapters use the minimal ABI of pinned game revision `955ce16a59b0efecf6ccdf2d391ede83de8902a8`. ABI compatibility and the recorded runtime code hash do not establish compiled bytecode equivalence. Only Base Sepolia (84532) is accepted. The signer CLI applies the shared full configuration validator; the signer library additionally pins game, auth adapter, identity registry and owner to `integration/shared/runtime-source.json`. A new deployment requires an explicit reviewed update to that pin. Tests inject a fixture deployment into the library; the CLI has no override for it.

`createChainReader({config, provider?})` reads every snapshot at one confirmed block, checks its canonical hash again, and filters event history to confirmed blocks. `preflight()` refreshes owner, auth adapter, defaults, runtime bytecode hash, roster admission, identity keys, testnet ETH balances, and cause whitelist flags. `readEvents()` produces completed/cancelled counts only from terminal events, resolved choices only from `EffectiveChoiceMaterialized`, and net player awards from historical terminal game state. Claims carry net amounts separately. A snapshot's terminal `transaction_hash` can be null; the authoritative result link comes from terminal events. Query history must begin no later than the demo's selected start block.

The default confirmation depth is two blocks. `readBlockHash({blockNumber})` checks actual RPC `eth_chainId` before returning the canonical block hash for restart/reorg checks. Normalized integers are decimal strings except round/counters/log index. The exact on-chain enum is Share=1, Catch=2, Steal=3. Joining advances strictly after the timestamp deadline; committing/revealing advances when all required players acted or strictly after its block deadline. Eliminated players can make terminal committed/revealed counts exceed alive count.

RPC configuration requires HTTPS but does not restrict the hostname to a vendor. Both chain identity and canonical readback still depend on the configured RPC's honesty; chain ID and ABI-compatible responses are not source verification or RPC attestation. The signer rechecks actual `eth_chainId` immediately before broadcast and during recovery rather than trusting a cached ethers network setting.

Run commands from `integration/conference-runner`:

```sh
node src/chain/cli.mjs preflight /absolute/conference-config.json
node src/chain/cli.mjs operator /absolute/conference-config.json /private/runtime/operator 8791
node src/chain/cli.mjs reconcile-operator /absolute/conference-config.json /private/runtime/operator
node src/chain/cli.mjs configure-defaults /absolute/conference-config.json /private/runtime/operator /absolute/defaults.json
```

The conference uses one existing owner/operator wallet for both game creation and phase advancement. The operator process uses `DILEMMA_LAUNCHER_PRIVATE_KEY` and, when serving HTTP, `DILEMMA_SIGNER_TOKEN` of at least 24 characters. Its signer must match the pinned owner and cannot be a roster player. No additional phase wallet is required. The CLI rejects other recognized player/owner/phase signing-key environment variables. Keep the operator environment and journal separate from the coordinator and private player runtimes. Keys are never accepted in command arguments, forwarded to players, printed, or persisted by these adapters. Runtime paths and their existing ancestors are resolved before creation; symlinks into the repository and repository ancestors are rejected. The coordinator receives the operator URL and authentication token. The service binds to loopback, default port 8791. Remote connections require a TLS proxy; do not expose the private directory.

Operator HTTP exposes authenticated `POST /create` and `POST /advance` in the same process. Existing `createLauncherClient` and `createPhaseExecutorClient` both point to that one URL/token; their method and request signatures are unchanged. Operation selection is explicit, advancement still validates the full core intent, and each persisted action ID is bound to its operation. No HTTP operation changes defaults. The separate `configure-defaults` command opens the same operator journal, requires all nine fields using the Solidity names in `abi.mjs`, preserves both current fee BPS fields, refreshes owner/auth/idle/network, submits the full tuple, waits for confirmation and compares all nine readback values. Stop the operator service before configuration or reconciliation using its journal directory. As with all live writes, run only within the user's existing authorization.

Intent is fsynced before signing; nonce and deterministic hash are fsynced before broadcast. One process lock, serial queue, and durable journal govern both operations and their shared nonce space. A pending signer nonce absent from this journal blocks new submission, and the populated transaction must use the expected nonce. Duplicate intents reconcile receipts/mempool membership instead of rebroadcasting. An unknown creation transaction blocks advancement and an unknown advancement transaction blocks creation until confirmed or manually reconciled; changing action IDs does not bypass that gate. Safe pre-submission rejections and confirmed reverts permit a fresh-block retry. A crash after hash persistence but before broadcast can therefore require operator reconciliation. This is an explicit safety boundary, not a promise of automatic replacement. Never delete the private journal to force a retry; establish the nonce and chain outcome first.

Legacy single-operation roles remain available for compatibility, but the conference commands above use only the operator. Existing legacy journals remain role-bound; reconcile their pending transactions before changing service arrangement.

All local tests use explicit fixtures. Running preflight is read-only; no game is live-proven until the lead records real agent transactions and terminal events.
